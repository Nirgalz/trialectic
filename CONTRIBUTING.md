# Contributing to the Trialectic Method

Thank you for your interest in improving the Trialectic Method. This is a
developing analytical framework, not a scientifically validated theory.
Contributions should improve clarity, consistency, reproducibility, or
critical evaluation without treating open questions as settled.

## Ways to contribute

- Open an issue to report ambiguities, inconsistencies, missing references,
  methodological limitations, or potential research questions.
- Propose examples, translations, comparisons, or corrections with a clear
  explanation and, where applicable, supporting sources.
- Submit a pull request for documentation improvements. For substantive
  conceptual changes, discuss the proposal in an issue first.

## Proposal and review process

1. Describe the problem, the proposed change, its rationale, and the
   definitions or sections it would affect.
2. Distinguish **VALIDATED** (explicitly approved), **FORMALIZATION**
   (a working expression of approved decisions), and **OPEN**
   (unresolved or proposed). Do not relabel a proposal as validated.
3. Keep changes focused; link the issue or decision under discussion.
4. For conceptual changes, wait for the author's explicit approval before
   integrating them into the maintained reference. A pull request is a
   proposal, not automatic approval.
5. After approval, update the reference, [TODO](TODO.md), and
   [decision log](DECISIONS.md) as applicable. Record the previous wording,
   new wording, reason, consequences, date, and validation status.
6. Preserve the version history. Do not silently rewrite past decisions.
   Maintainers review contributions and may request changes or decline them.

## Pull request checklist

- [ ] The change has a clear purpose and limited scope.
- [ ] Terminology matches the [glossary](terminology/french-english-glossary.md)
      or deviations are explicitly explained.
- [ ] Observations, hypotheses, estimates, and normative judgments are distinguished.
- [ ] References are provided for external factual or scientific claims.
- [ ] No unapproved conceptual decision is presented as validated.
- [ ] Related documentation, tasks, and decisions are updated when applicable.
- [ ] The pull request describes any changes to existing definitions.

## Language and documentation

English is the language of the maintained reference and repository
documentation. Discussion may take place in English or French. Translations
must preserve technical distinctions and identify the source version.
Do not assume that an unofficial translation changes the authoritative
English wording.

Use clear Markdown, descriptive headings, and relative links within the
repository. Prefer small, reviewable changes. Keep diagrams and examples
consistent with the text; label hypothetical scenarios as hypothetical.

## Repository of record

GitHub is the sole active repository for maintained reference documents,
decisions, tasks, and version history. Dropbox and Dropbox Paper are
not part of the current contribution workflow.
